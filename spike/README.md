# 스파이크 — 도트를 로우폴리로 바꿀 수 있는가

Copycat 을 3D 로 옮기는 게 가능한지 묻기 전에, **아트가 아니라 배포·상주 구조가 먼저 깨지는지**를 본다.
시뮬레이션(`sim.js` · `world.js` · `game.js` · `cats.js` · `care.js`, 약 2,000줄)은 렌더러를 모른다.
격자 좌표와 BFS 로만 돌아가서 그대로 살아남는다. 위험한 건 그 바깥이다.

그래서 스파이크는 세 개다. 셋 다 "예쁜가"를 묻지 않는다.

| | 질문 | 아니오면 |
|---|---|---|
| 0 | 빌드 없이 `.html` 한 장으로 `file://` 에서 돌아가는가 | 배포 모델을 통째로 다시 짠다 |
| 1 | WebGL 캔버스가 Document PiP 창을 건너가서도 사는가 | 위젯 모드가 죽는다 = 이 게임의 이유가 죽는다 |
| 2 | 하루 종일 켜 둘 만한 전력인가 | 사용자가 그냥 끈다 |
| 3 | 에셋 없이 코드로 짠 로우폴리가 봐줄 만한가 | 팩을 사야 하고 라이선스·스타일 문제가 따라온다 |

## 빠른 실행

```
cd copycat
node spike/serve.js          # 서버를 켜 두고 브라우저로 아래 주소들을 연다
```

| 무엇 | 주소 |
|---|---|
| **게임 · 3D** | `http://localhost:8123/index.html?3d=1` |
| **게임 · 도트(기본)** | `http://localhost:8123/index.html?3d=0` |
| **손그림 고양이** | `http://localhost:8123/spike/k9-doodle.html` |
| 배치 프로토타입 | `.../spike/c1-cardboard.html` … `c9-widgetcam.html` |
| 고양이 조형 | `.../spike/k1-face.html` … `k8-quad.html` |
| **깎은 고양이 · 6면도** | `.../spike/m1-sculpt.html` |
| 그림체 · 색 | `.../spike/f1-block.html` … `f8-cutout.html`, `s1-cream.html` … `s6-paper.html` |
| PiP · 전력 | `.../spike/1-pip.html`, `.../spike/2-power.html` |

3D 는 ES 모듈이라 **`index.html` 을 더블클릭(file://)하면 안 뜬다** — 그때는 도트로 돌아간다.
서버로 열어야 3D 가 붙는다.

손그림을 새로 그렸으면 자르는 것부터:

```
node tools/split-doodles.js   # assets/cats_drawn/cat.png → cat-1.png, cat-2.png …
```

## 실행 (그 밖)

```
node spike/serve.js                     # 개발용 — http://localhost:8123/spike/f7-blend.html
node spike/pack.js all                  # 단일 파일로 묶기 → spike/dist/*.single.html
node spike/verify.js                    # 헤드리스 크롬으로 전부 뜨는지 확인 + 스크린샷
node spike/verify.js f7-blend.single.html   # 하나만
node spike/sheet.js f                   # f* 스크린샷을 한 장으로 → dist/shots/_sheet-f.png
```

개발할 땐 서버가 필요하다(ESM 은 `file://` 에서 import 가 막힌다).
**배포 경로 검증은 `dist/` 의 단일 파일을 `file://` 로 직접 열어서** 한다 — 그게 진짜 테스트다.
좌하단 배지가 어느 경로로 떴는지(blob / data) 알려준다.

three.js 는 `vendor/` 에 받아 두었다(MIT). 갱신하려면:

```
curl -sL -o spike/vendor/three.module.min.js https://unpkg.com/three@0.185.1/build/three.module.min.js
curl -sL -o spike/vendor/three.core.min.js   https://unpkg.com/three@0.185.1/build/three.core.min.js
```

## 지금까지 나온 것

### ✅ 0 — 단일 파일 배포는 살아남는다

`three.module.min.js` 는 `three.core.min.js` 를 import 하는 두 조각이다. 그냥 이어붙이면 안 된다 —
둘 다 최상위 식별자가 minify 되어 있어서 `e`, `t` 가 충돌한다. 그래서 **모듈을 모듈인 채로 두고
specifier 만 blob URL 로 갈아끼운다**(`pack.js`). `file://` 에서 확인:

```
[pack] 단일 파일 · blob: 모듈 OK · file:
```

blob 이 막히는 브라우저를 위해 `data:` URL 폴백도 넣어 두었고, 어느 쪽으로 떴는지 화면에 찍는다.

**비용: 335 KB → 790 KB.** 지금 배포본(`dist/copycat.html`)의 2.4배다. three.js 만 750 KB.
음악까지 넣은 배포본이 이미 7.4 MB 인 걸 생각하면 감당 못 할 숫자는 아니다.

> 함정 하나 기록: `html.replace(match, loader)` 로 문자열을 넘기면 three 코드 안의
> `$&` · `` $` `` · `$'` 가 치환 패턴으로 해석돼서 페이로드 한가운데에 엉뚱한 HTML 이 박힌다.
> 반드시 함수로 넘긴다. 이거 하나 때문에 세 파일이 전부 조용히 깨져 있었다.

### ⚠️ 2 — 드로우콜이 먼저 터진다

18×14 사무실 + 고양이 8마리에서:

```
draw call 1131  ·  삼각형 13,572
```

**삼각형은 아무것도 아닌데 드로우콜이 1,100 이다.** 로우폴리의 비용은 폴리곤이 아니라
"박스 하나 = 메시 하나"에 있다. 바닥 타일 252개, 가구 부품 수백 개가 전부 개별 드로우콜이다.
26×22 냥타워 등급이면 1,600 을 넘는다.

→ 정적인 것(바닥·벽·가구)은 **병합하거나 InstancedMesh 로** 묶어야 한다.
`2-power.html` 의 [바닥 인스턴싱] 스위치로 차이를 바로 볼 수 있다.
움직이는 건 고양이뿐이라 병합 대상은 명확하다.

### ✅ 3 — 코드로 짠 로우폴리는 봐줄 만하다

`lib/lowpoly.js` — 박스가 유일한 원시 도형이다. 에셋 파일이 0개다.
책상·의자·모니터·화분·책장·자판기·정수기·낮잠상자·결재함, 그리고 **박스 14개짜리 고양이 리그**.

`dist/shots/3-lowpoly.png` 참고. 여기서 딸려 온 것들:

- **스타일 통일이 공짜다.** 팔레트 하나, 머티리얼 하나, 폴리 밀도 하나. 팩을 섞을 때 나는 어긋남이 없다
- **아틀라스 파이프라인이 통째로 사라진다.** `build-atlas.js` · `pick()` · 좌표 검증 · 유료 원본 유출 검사가 전부 불필요해진다
- **`tall`/`wide` 슬라이싱과 `z-index: 10 + y*4` 수동 깊이 정렬도 사라진다**
- **장비가 겉모습에 붙는다.** README 가 "분명한 손실"이라고 적어둔 그것 — 여기선 머리 그룹에 박스 두 개다
- **털색 제한이 없어진다.** `hue-rotate` 4시트 × 8회전 = 24종이던 게 그냥 색값이 된다
- 이름표·말풍선은 3D 좌표를 투영해서 DOM 을 얹으면 그대로 산다 (`updateTags()`)

한계도 같이 나왔다: 고양이는 실제 비율(한 칸의 절반)로 두면 안 읽혀서 1.25배 키웠다.
도트판도 같은 거짓말을 하고 있으니 새로운 부채는 아니다.

## 그림체 프로토타입 — 한 번에 한 축만

"3D 로 갈 수 있는가" 다음 질문은 "어떤 3D 인가" 다. 색과 형태를 같이 바꾸면
뭐가 좋았는지 알 수 없으므로 축을 나눠서 본다.

전부 같은 장면을 **오전 10시 · 퇴근 무렵 18시 · 야근 23시** 세 패널로 동시에 그린다.
copycat 은 실제 시계로 도는 게임이라 톤이 하루를 버텨야 하기 때문이다.
낮에만 예쁜 팔레트는 여기서 못 쓴다. 패널을 클릭하면 그 시간만 크게 본다.

### 1축 — 색 (`s1`~`s6`) · 형태는 f1 고정

| | 방향 | 성격 |
|---|---|---|
| s1 | 크림 오피스 | 지금 도트 UI 와 같은 온도. 기준선 |
| s2 | 황혼 야근 | 서늘한 남보라 기조 + 따뜻한 점광. 오후·밤에 강함 |
| s3 | 파스텔 디오라마 | 고명도 저채도. 밤에도 안 어둡다 |
| s4 | 네온 밀실 | 창 없는 반지하, 청록·마젠타. 농담은 사는데 눈이 피곤 |
| s5 | 모노크롬 + 원포인트 | 캣닢과 서류만 색. 색이 곧 게임 상태 |
| s6 | 종이 공작 | 무광 + 윤곽선. 시간을 빛이 아니라 종이 색으로 |

**→ s3 채택.** 이후 형태 프로토타입은 전부 이 팔레트(`lib/pastel.js`)를 쓴다.

### 2축 — 형태 (`f1`~`f7`) · 색은 s3 고정

그림체는 `lowpoly.js` 의 `KIT` 하나로 결정된다. 가구도 고양이도 전부 `box()` 를
지나므로, `box()` 가 무엇을 만드느냐만 바꾸면 사무실 전체가 통째로 바뀐다.
가구 함수는 한 줄도 안 고친다.

```js
KIT = { prim:'sharp'|'round', bevel, voxel, shading:'flat'|'smooth'|'toon',
        detail:0|1, cat:{ head, leg, body, ear, tail } }
```

| | 방향 | 손잡이 | 참고 |
|---|---|---|---|
| f1 | 각진 박스 | 기준선 | Crossy Road · Kenney |
| f2 | 복셀 (1/8 격자) | `voxel:0.125` | Cube World · MagicaVoxel |
| f3 | 라운디드 소프트 | `prim:'round'` + `smooth` | Townscaper · Dorfromantik |
| f4 | 치비 비율 | `cat:{head:1.5, leg:0.55}` | Animal Crossing · Dear My Cat |
| f5 | 툰 + 윤곽선 | `shading:'toon'` + outline | Lil Gator · Alba |
| f6 | 극단적 미니멀 · 직교 | `detail:0` + ortho | Islanders · Monument Valley |
| f7 | 종합 후보 | f3+f4+f5 를 겹친 것 | — |
| f8 | 종이 인형 2.5D | `cutout:true` | Paper Mario · 지금 스프라이트를 세운 것 |

f8 만 성격이 다르다. 나머지 일곱은 "도트를 버리고 무엇이 되느냐" 인데, f8 은
**도트를 안 버리는 길**이다 — 무대(바닥·벽)만 3D 로 두고 물건과 고양이는 납작한 판으로
세워서 카메라를 보게 한다. 지금의 16×16 자산이 그대로 살고, 깊이·조명·그림자·시간대 색만
얹힌다. 갈아타는 비용이 제일 싸고, 대신 "3D 로 바꿨다"고 말할 수 있는 그림은 아니다.

`node spike/sheet.js f` 로 일곱 개를 한 장에 붙여 놓고 본다. 탭을 오가며 보면
눈이 적응해서 "둘 다 괜찮은데"로 끝난다.

### 그림체가 무는 값 (같은 장면, 3패널 기준)

| | draw call | 삼각형 |
|---|---|---|
| f1 각진 | 308 | 3,696 |
| f2 복셀 | 308 | 3,696 |
| f3 라운디드 | 308 | **33,264** |
| f4 치비 | 308 | 3,696 |
| f5 툰+윤곽선 | **477** | 3,696 |
| f6 미니멀 | **198** | 2,176 |
| f7 종합 | 477 | 33,264 |

스파이크 2에서 확인된 병목은 **삼각형이 아니라 드로우콜**이다. 이 표를 그 사실 위에 놓으면
선택이 꽤 분명해진다:

- **모서리를 깎는 건 거의 공짜다.** 삼각형이 9배가 되지만 드로우콜은 그대로고,
  이 게임은 삼각형에 여유가 많다.
- **윤곽선은 비싸다.** 오브젝트마다 LineSegments 를 하나씩 더 그려서 드로우콜이 +55%.
  하필 우리가 못 내주는 자원이다. 쓰려면 후처리(post-process) 윤곽선으로 바꿔야 한다.
- **디테일을 빼면 드로우콜이 1/3 넘게 준다.** 위젯 모드에서 형태를 바꿔 끼우는 근거가 된다.

### 여덟 장을 놓고 읽은 것

- **귀여움은 재질이 아니라 비율에서 온다.** f1 → f4 는 가구가 한 줄도 안 바뀌고
  고양이 머리/다리 비율만 바뀌는데 게임의 인상이 제일 크게 움직인다.
- **파스텔은 각진 형태와 잘 안 맞는다.** 채도가 낮은 색끼리 각지게 붙으면
  "덜 그려진 것"처럼 보이는데, 모서리를 깎으면(f3) 같은 색이 "일부러 그런 것"이 된다.
- **직교(f6)는 미학이 아니라 가독성 카드다.** 원근이 없으면 뒷줄이 안 작아진다.
  380px 위젯에서 유리하고, 대신 사무실이 넓어 보이지 않는다.
- **f8 은 다른 축이다.** 갈아타는 비용이 제일 싸고 도트 자산이 산다. 다만 이걸 고르면
  "3D 로 바꿨다"가 아니라 "무대를 3D 로 깔았다"가 된다 — 홍보 문구가 달라진다.

### 3축 — 배치 (`c1`~`c6`) · 색과 형태 고정

**→ f3 라운디드 소프트 채택.** `lib/office.js` 가 그림체(f3)와 색(s3)을 붙박이로 들고 있고,
프로토타입은 `build(ctx)` 안에서 물건을 놓기만 한다. 이제 움직이는 축은 배치 하나뿐이다.

여기서부터는 3패널을 그만두고 **한 화면**만 그린다. 볼 것이 톤이 아니라
"이 사무실이 아늑한가" 라서 화면을 쪼개면 오히려 안 보인다. 시간대는 버튼으로 갈아 끼운다.

| | 가설 | 방 |
|---|---|---|
| c1 | 아늑함의 첫 재료는 **작음**이다. 물건을 늘리는 대신 방을 줄인다 | 7×6 |
| c2 | 통로를 한 칸만 남기고 가구를 민다 | 10×8 |
| c3 | 큰 방을 낮은 칸막이와 바닥재로 **쪼갠다** | 12×9 |
| c4 | 바닥이 아니라 **위**를 채운다 — 캣워크·벽선반·펜던트 | 10×8 |
| c5 | **창**을 낸다. 창밖 색이 곧 시계가 된다 | 11×8 |
| c6 | 가구는 그대로, **잡동사니**만 몇 배로 | 9×7 |

`ctx` 가 주는 것: `put(o,x,z,ry,y)` · `pod(x,z)` (책상+모니터+의자 한 짝) ·
`onWallN/onWallW` (벽에 걸기) · `lamp(o)` (시간대에 맞춰 켜지는 광원 등록) ·
`cat(...)` · `walker(...)`. 새 배치안 하나를 만드는 비용이 40줄쯤이다.

cozy 재료도 `lowpoly.js` 에 같이 들어갔다 — `partition` · `wallShelf` · `wallArt` ·
`catwalk` · `pendant` · `windowUnit` · `sunPatch` · `catTower` · `whiteboard` ·
`wallClock` · `mug` · `cardboard` · `cushion` · `blanket` · `snackBowl`.

c4 와 c5 는 **지금 게임이 구조적으로 못 하던 것**이라 따로 볼 값어치가 있다.
위에서 내려다보는 2D 격자에는 벽 선반도 천장 조명도 놓을 자리가 없었고,
창문은 "타일셋에 맞는 창문 타일이 없어서" 아예 뺐다고 README 에 적혀 있다.

### 4축 — 고양이 조형 (`k1`~`k4`) · 배경 없음

사무실도 가구도 치웠다. 조형 하나를 판단할 때 배경이 있으면 배경이 대신 답한다.
같은 조명·같은 각도·정면으로 여덟 마리를 한 줄에 세우고 한 축씩만 바꾼다.

캐릭터는 `lib/cat3.js` — 가구와 달리 **다면체**로 짠다. 참조 피규어 같은 "각진 구"는
박스로 안 나온다. 정이십면체(detail 0 이면 20면, 1 이면 80면) · 각뿔 · 위아래 굵기가
다른 기둥, 이 셋이 전부다. 가구는 박스, 캐릭터는 다면체 — 면이 보이는 건 같아서 붙는다.

**확정된 기준형** (`BASE`):

- **2등신** — 머리가 전체 키의 절반
- **큰 귀** — 이 실루엣에서 "고양이"라고 말해주는 건 사실상 귀뿐이다
- **주둥이 없음** — 빼면 얼굴이 평면이 되고, 평면이라야 이목구비가 읽힌다
- **이목구비를 아래로** — 위로 올리면 즉시 어른 얼굴이 된다 (`eyeUp` 이 음수)
- **작은 몸** — 머리를 받치는 받침에 가깝게

| | 축 | 본 것 |
|---|---|---|
| k1 | 머리 덩어리 | 가로/세로/앞뒤 비율 · 볼살 · 면 수 · 이마 |
| k2 | 이목구비 | 눈 종류 5가지 · 눈 간격 · 입 유무 |
| k3 | 귀와 등신 | 귀 4단계 · 1.7 / 2 / 2.5등신 · 네 발 대조군 |
| k4 | 장비 | 비니 · 캡 · 고깔 · 목도리 · 방울 목걸이 · 망토 · 헤드폰 |

k4 가 이 축에서 제일 값어치 있다. 게임에는 이미 장비 3슬롯(머리/목/발)이 있는데
README 에 "능력치에만 반영되고 겉모습은 안 바뀐다 — 분명한 손실"이라고 적혀 있다.
고정된 도트 시트로 합성이 안 됐기 때문이다. 두 발로 서는 3D 캐릭터에서는
머리 그룹에 도형 몇 개를 더하면 끝이고, **분기 결산 드랍이 화면에 보이는 보상이 된다.**

계기판의 [작게 보기 380px] 가 실제 판정 기준이다 — 위젯 모드에서 구분이 안 되면
아무리 예뻐도 못 쓴다.

### 확정판과 드로우콜 (`c7` · `c8`)

네 축이 다 정해진 뒤 실제 조건에 넣은 것: **s3 파스텔 · f3 라운디드 소프트(가구) ·
c4 수직 배치 · k8 ⑧ 캐릭터**. 10×8 사무실에 고양이 20마리.

`c8` 은 같은 사무실을 380×300 위젯 크기로 띄운다. 이게 실제 판정 기준이다 —
copycat 은 근무 시간 내내 옆에 떠 있는 게임이라 사용자가 보는 건 전체 창이 아니다.

**병합 전 1,295 → 병합 후 388.**

`lib/merge.js` 가 하는 일은 하나다: **색을 정점에 구워 넣는다.** 보통은 같은 머티리얼끼리
묶는데 여기서는 색이 곧 물건이라 머티리얼이 수십 개다. 색이 지오메트리 안으로 들어가면
머티리얼이 하나가 되고, 하나가 되면 전부 한 번에 그려진다.

규칙 둘로 예외를 관리한다:
- `userData.dynamic` — 런타임에 머티리얼이 바뀌는 것(모니터 화면 · 전구). 안 합친다
- `userData.keep` — 따로 움직여야 하는 묶음(눈 · 꼬리 마디). 거기서 하강을 멈춘다

고양이는 리그 묶음 단위로만 합친다 — 머리 · 몸 · 다리 넷 · 꼬리 둘 · 눈 한 벌 = **9콜**
(합치기 전 34콜). 귀 씰룩임은 여기서 포기했다. 귀를 머리에 구워 넣는 대신 머리가
드로우콜 하나가 된다. 20마리 규모에서는 그 거래가 맞다.

남은 여지: 앉아 있거나 자는 고양이(16마리)는 통째로 1콜까지 줄일 수 있다.
상태가 바뀔 때 다시 만들면 되고, 그러면 388 → 150 근처가 된다. 필요해지면 그때.

### 380px 에서 나온 결론

방으로는 읽힌다. 그런데 **개체 구분이 안 되고 표정이 안 보인다** — 마리당 15px 남짓이다.
상태 연동 표정(^ ^ / 뜬 눈 / 감은 눈)이 정작 제일 오래 보는 화면에서 안 보인다.

→ 위젯 모드는 사무실 전체를 보여주면 안 된다. 한 구역을 확대하거나 사건을 따라가야 한다.

그리고 **위젯이라고 더 싸지지 않는다.** 전체 화면과 380px 의 드로우콜이 같다.
창이 작아도 씬은 그대로 그린다.

## 5축 — 조형 방식 (`m1`) · 붙이는 대신 깎는다

k1~k8 은 전부 **붙이는** 방식이었다. 정이십면체 머리에 원뿔 귀를 얹고 기둥 다리를 꽂는다.
그런데 참조 피규어(`cat3.js` 머리말의 레퍼런스 ①)를 다시 보면 붙인 물건이 아니다.
**목이 없는 게 아니라 목이 녹아 있다.** 다리가 몸에 꽂힌 게 아니라 몸에서 자라나 있다.
이음매가 한 군데도 없다. 부품을 아무리 잘 놓아도 이건 안 나온다 — 표면이 하나여야 나온다.

그래서 `lib/sculpt.js` 는 순서를 뒤집는다.

1. 뼈대를 **거리장(SDF)** 으로 적는다 — 굵기가 변하는 캡슐 33개. 이게 설계도다
2. **부드러운 합집합**(`smin`)으로 녹인다 — `k` 가 곧 이음매의 반지름이다
3. 격자에서 **surface nets** 로 껍질 하나를 뽑는다
4. flat 으로 칠한다

마칭큐브 대신 surface nets 를 쓴 건 미학이다. 마칭큐브는 삼각형이 격자 대각선을 따라
찢어지는데, surface nets 는 셀마다 정점 하나를 놓고 사각형으로 잇는다.
**크기가 고른 사각면**이 나오고, 그게 참조 피규어의 그 면이다.
표도 필요 없다 — 256줄짜리 삼각형표 대신 모서리 12개면 끝이다.

`m1-sculpt.html` 은 참조와 **같은 형식으로** 판정한다. 회색 배경, 스튜디오 조명,
여섯 컷의 회전표(앞·뒤·옆 / 3⁄4·위·아래). 3⁄4 컷만 드래그로 돌아간다.
[뼈대] 를 누르면 껍질 안에 캡슐 설계도가 그대로 비친다.

### 나온 것

- **면의 크기 = 격자 해상도.** 그림체 손잡이가 `res` 하나로 줄었다. 낮추면 "덜 만들어진 것"이
  되는 게 아니라 **더 로우폴리가 된다.** 참조의 면 크기는 `res` 30 근처다
- **고양이 한 마리 = 메시 하나 = 드로우콜 1.** `cat3.js` 리그는 병합하고도 9콜이었다
- **비율이 숫자다.** 부품을 다시 붙이는 게 아니라 캡슐 좌표만 바뀐다.
  프리셋 다섯(레퍼런스·치비·길쭉·덩어리·아기·웅크림)이 전부 같은 생성기에서 나온다

| `res` | 삼각형 | 성격 |
|---|---|---|
| 24 | 2,372 | 면이 크다. 귀가 뭉개지기 직전 |
| 30 | 3,676 | **참조와 면 크기가 같다** |
| 36 | 5,248 | 기본값. 실루엣과 면이 둘 다 산다 |
| 48 | 9,548 | 매끈하다. 이미 로우폴리가 아니다 |
| 60 | 14,784 | 발바닥 젤리가 살아나는 최소선 |

삼각형 수는 결정적이라 그대로 적었고, 생성 시간은 헤드리스 소프트웨어 렌더 기준
70~180 ms 사이로 편차가 커서 자릿수만 본다. 어느 쪽이든 **한 번 만들고 재사용**하는 비용이다.

### 얼굴 — 조형이 아니라 칠 (`lib/facepaint.js`)

눈과 입을 다는 방법은 보통 둘이다. 도형을 더하거나(`cat3.js` 가 그렇게 한다),
텍스처를 감거나. 여기서는 둘 다 손해다.

- 도형을 더하면 **부품이 생기고**, 부품이 생기면 이 방식의 유일한 소득인
  "메시 하나 = 드로우콜 하나" 가 깨진다
- 텍스처를 감으려면 UV 가 있어야 하는데, 격자에서 뽑은 껍질에는 UV 가 없다.
  비율 슬라이더를 움직일 때마다 UV 를 다시 펴야 한다

그래서 세 번째 길로 간다 — **오브젝트 공간에서 바로 칠한다.**
머리를 단위구로 되돌려 놓으면(중심을 빼고 반지름으로 나누면) 얼굴 위의 자리가
방향 벡터 하나로 정해진다. 눈은 "정면에서 옆으로 몇 도, 아래로 몇 도" 인 방향이고,
그 방향의 접평면에서 타원 하나를 그리면 그게 눈이다. 입은 원 두 개의 아래쪽 반 — ω.
`MeshStandardMaterial` 의 `diffuseColor` 한 줄만 가로채므로 조명·그림자·flat 셰이딩은
three 것을 그대로 받는다.

- **정점이 하나도 안 는다.** 삼각형 5,248 · 드로우콜 1 — 칠하기 전과 같은 숫자다
- **면 크기와 무관하게 선명하다.** `res` 24 로 깎아도 눈매는 안 뭉갠다.
  조형으로 붙였다면 눈이 셀보다 작아져 사라졌을 것이다 — 발바닥 젤리가 그랬듯이
- **표정이 uniform 하나다.** k8 이 정해 둔 상태 연동(idle=^ ^ · sit=뜬 눈 · sleep=감은 눈)이
  여기서는 다시 깎지도, 지오메트리를 건드리지도 않는 숫자 하나가 된다

크기는 **작게, 간격은 넓게, 안광은 끈다** 로 정했다. 큰 눈은 즉시 마스코트가 되는데
이 실루엣은 피규어 쪽이라 이목구비가 작아야 조형이 주인공으로 남는다.
k1~k8 의 치비 계열과 정반대 방향이고, 몸을 깎아서 만든 이상 이쪽이 맞다.

안광은 k7 이 "구멍을 눈으로 만드는 제일 싼 레버" 라고 적어 둔 것인데, **그건 눈이 클 때
얘기였다.** 이 크기에서는 점 하나가 이미 눈으로 읽히고, 하이라이트를 넣으면 점 안에
점이 생겨서 지저분해진다. 손잡이는 남겨 뒀고 기본값이 0 이다 — 눈을 다시 키우면 켤 값이다.

여기서 새로 생긴 문제가 하나 있다. **바탕이 어두우면 잉크가 안 보인다.**
도트 시절엔 고양이 색마다 시트를 손으로 그렸으니 없던 문제고, 바탕색을 값으로
바꾸는 순간 생긴다. 밝기를 재서 뒤집는 것으로 해결했다 — 어두운 바탕에는
밝은 획 + 어두운 하이라이트. 검정 고양이의 눈을 밝게 그리는 건 만화에서도 하는 일이다.

| 컷 | |
|---|---|
| `m1-face-뜬눈.png` | 기본 · 주황 |
| `m1-face-웃는눈.png` | idle 표정 ^ ^ |
| `m1-face-감은눈.png` | sleep 표정 |
| `m1-face-검정.png` | 어두운 바탕 → 획 색이 뒤집힌다 |
| `m1-face-흰색.png` | 밝은 바탕 |

### 부딪힌 것

- **몸 굵기를 올리면 다리가 통째로 잡아먹힌다.** `smin` 은 가까운 것을 전부 녹이므로
  첫 판이 돼지 저금통이 됐다. 붙이는 방식에는 없던 실패 모드다
- **귀 끝을 뾰족하게 두면 톱니가 된다.** 셀보다 얇은 건 격자가 못 잡는다.
  끝을 조금 뭉툭하게(`earTip`) 남겨야 한다 — 참조도 실은 뭉툭하다
- **발바닥 젤리는 `res` 60 을 넘겨야 나온다.** 계기판이 `발가락젤리/셀` 배수를 찍는다.
  1 배 미만이면 통째로 사라진다. **몸에 맞는 격자와 젤리에 맞는 격자가 다르다** —
  균일 격자의 한계고, 참조 피규어는 손으로 데시메이트해서 면 밀도가 고르지 않다
- **여기서도 주둥이는 빼는 게 맞았다.** k1~k8 이 낸 결론이 조형 방식을 바꿔도 그대로 산다 —
  붙이면 즉시 고양이가 아니라 동물이 된다. 턱은 주둥이 대신 **볼**(`cheek`)로 넓힌다.
  손잡이는 남겨 뒀지만 기본값은 0 이다
- **부품이 없다는 건 귀를 따로 못 씰룩인다는 뜻이다.** k4 의 장비 슬롯(모자·목도리)도
  머리 그룹에 도형을 더하는 식으로는 안 붙는다 — 캡슐로 적어서 같이 녹이거나, 따로 얹거나

### 게임으로 승격 (완료)

`lib/sculpt.js` · `lib/facepaint.js` 를 `js/three/` 로 올리고 `catsculpt.js` 를 붙였다.
**기본 그림체가 조형이 됐고, 손그림은 설정에서 고를 수 있게 남겼다**(`?cat=doodle`).

승격하면서 시트에서는 안 보이던 것 셋이 나왔다.

- **자세가 하나로는 안 된다.** 사무실 고양이는 하루의 대부분을 의자에 앉아 있는데
  네발로 선 몸을 의자에 얹으면 그냥 의자 위에 서 있는 그림이다.
  그래서 다리를 접는 손잡이(`legFold` · `bodyTilt`)를 넣고 자세 셋(서 있음·앉음·식빵)을 깎았다.
  **자세마다 모델을 만드는 게 아니라 숫자만 다르다** — 이 방식의 소득이 여기서 한 번 더 나온다
- **꼬리는 옆으로 흘려야 한다.** 앉은 자세에서 꼬리를 곧게 뒤로 늘어뜨리면 의자 등받이를 뚫는다.
  `tailSide` 를 만들어 좌판 옆으로 흘렸다 — 실제 고양이가 하는 것과 같다
- **앉는 자리는 재서 정해야 한다.** `lowpoly.chair` 의 좌판은 칸 기준 z +0.09~+0.51,
  등받이는 +0.45~+0.53. 손그림은 종잇장이라 +0.62(의자 앞)로 밀어 뒀는데, 조형을 그 값에
  그대로 두면 **허공에 뜬다.** 눈으로 고치려다 세 번 헛돌았고, 도형을 읽고 나서 한 번에 끝났다 —
  +0.20 이면 좌판 위이면서 꼬리 뿌리가 등받이 판을 안 건드린다

이름표도 이때 다시 만들었다. 흰 알약 칩 스무 개가 공중에 떠서 파스텔 사무실을 덮고 있었다.
지금은 **고양이 발밑에 적힌 흐린 글자**고, 카메라가 따라다니는 한 마리만 진해진다.

| 컷 | |
|---|---|
| `game-3d-sculpt.png` | 조형 (기본) |
| `game-3d-doodle.png` | 손그림 (설정에서 되돌린 것) |
| `index-seat7-crop.png` | 의자에 앉은 것 확대 |

### 다음 (`m2`)

**설계도가 곧 리그다.** 캡슐마다 `bone` 이름이 이미 붙어 있으므로(`head` · `legFR` · `tail0`…),
정점을 제일 가까운 캡슐에 묶으면 스키닝 가중치가 공짜로 나온다.
그러면 드로우콜 1을 유지한 채로 GPU 스키닝이 돈다. 그게 되면 "한 마리 1콜"이 진짜 숫자가 된다.
안 되면 자세마다 다시 깎아야 하고(50~70 ms), 20마리 규모에서는 못 쓴다.

## 6축 — 분위기 (`eerie`) · 형태는 그대로, 빛과 안개만

레퍼런스: PC Gamer 가 "Silent Hill × Animal Crossing × DoorDash" 라고 부른
로우폴리 배달 게임. 화면을 뜯어보면 겹쳐 있는 것은 네 가지다.

1. **색이 빠져 있다** — 한 벌로 묶인 팔레트. 채도가 낮다
2. ~~**안개가 두껍다** — 방 저쪽이 배경색으로 녹아 없어진다~~ → **안 쓴다**(아래)
3. **빛이 웅덩이로 있다** — 고른 전역광이 아니라 등 아래만 밝다
4. **해상도가 낮다** — 내부를 1/3.4 로 그리고 정수배로 늘려 픽셀이 각져 있다

1~3 은 팔레트·시간대표·안개로 되고, 4 만 후처리 한 장이 필요하다.
그래서 `js/three/eerie.js` 는 **표(색) + 패스(후처리)** 둘로 되어 있다.

### 두 판을 찍었다 — 그리고 그게 이 축의 결론이다

**1차(어두운 판).** 레퍼런스를 그대로 따라갔다. 회청색 팔레트, 전역광 0.3,
안개 색 `0x0B0E13`, 노출 0.55, 비네트 0.70. 분위기는 확실히 났는데 —
**같이 있어 주는 사무실이 아니라 혼자 남은 사무실이 됐다.**
이 게임은 근무시간을 같이 견뎌 주는 물건이라 그 톤은 못 쓴다.

**2차(지금).** 질감은 그대로 두고 **값만** 옮겼다. 각진 상자·평면 셰이딩·
저해상도·오더드 디더·안개는 1차 그대로다. 바꾼 것은 넷:

| | 1차 | 2차 |
|---|---|---|
| 팔레트 | 회청색 (`0x8A8D88` 계열) | 따뜻한 오트밀·크림 (`0xC7BAA7` 계열) |
| 전역광 (day) | hemi 0.36 · sun 0.30 | hemi 0.60 · sun 0.66 |
| 안개 색 (day / night) | `0x525A64` / `0x0B0E13` | `0xA99C8B` / `0x2E374C` |
| 후처리 | exp .55 · sat .34 · vig .70 | exp .80 · sat .82 · vig .32 |

**여기서 배운 것: 무섭게 만드는 건 어둠이 아니라 세 가지다.**

- **차가운 회색.** 파란 쪽 회색은 그 자체로 사람을 밀어낸다. 같은 밝기라도
  노란 쪽 회색으로 옮기면 같은 방이 "추운 방" 에서 "불 켠 방" 이 된다.
- **그늘에서 색을 빼는 것.** 1차는 밝은 데만 채도를 남겼다(등불만 유채색).
  그러면 그늘에 들어간 물건이 전부 회색 덩어리가 된다 — 그게 공포물의 문법이다.
  지금은 그늘도 자기 색을 갖는다. 그늘진 소파도 파란 소파여야 한다.
- **안개 색이 어두운 것.** 같은 두께라도 안개가 어두우면 "저쪽에 뭐가 있다",
  밝으면 "저쪽이 흐리다" 가 된다. 앞의 것이 공포이고 뒤의 것이 아침이다.

밤은 검정이 아니라 **깊은 남색**(`0x2E374C`)으로 두었다.
검정은 방이 없어진 것이고 남색은 방이 어두운 것이다.

### 붙인 방식 — 갈아엎지 않고 끼운다

`render3d.js` 에서 손댄 곳은 다섯 줄뿐이다.

| 자리 | 하는 일 |
|---|---|
| `init()` | `LP.setKit` · `LP.setPalette` 를 eerie 것으로, 후처리 설치 |
| `night()` | `TIME` 표를 eerie 것으로 갈아 끼우고 안개 색을 같이 옮긴다 |
| `fit()` | 렌더 타깃 크기 |
| `draw()` | `renderer.render` → 타깃에 그리고 전체 화면 한 장으로 뽑기 |
| — | `?style=eerie` / `?style=pastel` 로 켜고 끈다 |

**되돌릴 수 있어야 실험이다.** `?style=pastel` 로 원래 파스텔이 그대로 나온다
(`index-pastel.png` 로 확인). 1차 판의 값은 `eerie.js` 주석에 숫자로 남겨 두었다.

### 걸린 것 — 안개를 어디에 거는가

네 번 틀렸고, 넷 다 같은 실수의 다른 얼굴이었다.

1. **카메라 거리에 비례시켰다** (`near = dist × k`) → 줌아웃하면 안개가 걷히고
   줌인하면 코앞이 잠긴다. **줌이 날씨를 바꾸면 안 된다.**
2. **화면에 담긴 넓이로 바꿨다** (`h = dist·tan(fov/2)`, `near = dist − h·k`)
   → 줌과는 무관해졌는데 기준점이 여전히 **카메라**라서 화면 전체가 잠겼다. 우유가 됐다.
3. 기준점을 **보고 있는 지점**(= 화면 한가운데 = `dist`)으로 옮겼다.
   `fogK` 는 거기서 화면 몇 장 앞뒤인지를 말한다.
4. 시작점을 여전히 **음수**로 두고 있었다(`[-0.35, 1.90]` = 화면 한가운데보다
   조금 앞에서 시작). 그러면 **중간 책상부터 흐려진다** — 분위기는 나는데
   뒤쪽 절반이 없는 방이 된다. 양수로 옮겨서(`[0.55, 1.55]`) 앞 2/3를 살렸다.

### 그리고 결국 뺐다 — 안개 없음이 기본이다

세 번째 값까지 가고 나서 **끄는 스위치**를 붙였다(`R3E.fog(false)`).
"안개 색이 이 그림체의 전부다" 라고 위에 써 놓고도 그걸 반증할 손잡이가 없었다.
붙이고 세 단계를 나란히 찍었다(`dist/shots/_fog3-day.png` · `_fog3-night.png`).

| | 세게 (`-0.35`) | 약하게 (`+0.55`) | **없음 (채택)** |
|---|---|---|---|
| 앞·중간 책상 | 흐려진다 | 맑다 | 맑다 |
| 뒷벽·먼 자리 | 사라진다 | 녹는다(형체는 남음) | 또렷하다 |
| 깊이 | 있다 | 있다 | 없다 — 방이 평평하다 |
| 읽히는 것 | 분위기 | 분위기 + 자리 | 관리 게임 |

**깊이를 버리고 자리를 골랐다.** 이 게임은 골목을 걷는 1인칭이 아니라 사무실 하나를
위에서 내려다보는 것이고, 고양이가 20마리까지 늘어난다. 뒤쪽 자리가 안 보이면
그건 분위기가 아니라 정보 손실이다.

안개가 없어도 밤이 밤으로 읽힌다는 게 결정적이었다 — **창(짙은 남색)과 등불 웅덩이가
이미 그 일을 하고 있었다.** 안개는 거기에 한 겹 더 얹는 것이었고,
그 한 겹의 값이 뒤쪽 책상 넷이었다.

되살리는 자리는 남겼다: `R3E.fog(true)` 와 `TIME` 의 `fog` 값(절충안 숫자 그대로).

**나란히 놓고 봐야 판단이 됐다.** 하나씩 보면 셋 다 "괜찮은데" 로 끝난다
(그래서 `sheet.js` 가 처음부터 있었다).

그 밖에 하나 더 — **`night()` 안에 파스텔 팔레트가 직접 박혀 있었다.**
모니터·등·창 셋이 그림체를 안 따라와서 어두운 방에서 그것만 하얗게 떴다.
팔레트를 바꿀 수 있는 물건으로 만들려면 표를 참조하는 자리가 전부 "지금 팔레트" 를 봐야 한다.

### UI 도 같이 입힌다 (`style.css` 의 `body.eerie`)

화면 한가운데가 안개 낀 저녁인데 테두리만 크림색이면 두 벌의 게임처럼 보인다.
UI 도 1차는 차가운 검정(`#0F1319`)이었다가 **따뜻한 어둠**(`#171310`)으로 옮겼다 —
전원이 나간 화면이 아니라 스탠드 하나 켠 방의 색이다.
**색만** 갈아 끼웠다. 배치·글꼴·크기는 그대로다.

인라인 `style` 로 박혀 있던 카드 하나는 클래스(`.hirecard`)로 옮겼다 —
인라인은 어떤 규칙보다 세서 그림체를 갈아 끼워도 그것만 안 따라온다.

### 초상 — 마지막까지 다른 그림체로 남아 있던 곳

목록·기록증·면접창의 고양이 그림은 `catsculpt.sculptPortrait` 가 **작은 캔버스에 한 번 굽고
캐시하는** 물건이다. 매 프레임 도는 패스를 걸 자리가 없어서 그림체를 갈아입힐 때 통째로 빠졌고,
어두운 패널 위에 스튜디오 조명으로 구운 그림이 얹혀 **다른 게임에서 가져온 스티커**가 됐다.
목록에서 분홍 고양이만 형광색이었다.

고친 것 셋:

- **조명** — 흰 반구 1.25 + 흰 키 1.7(스튜디오) → 따뜻한 스탠드 키 + 찬 창 필(사무실).
  "그 방에서 찍은 사진" 이 되어야 목록이 사무실의 일부로 읽힌다
- **해상도** — `size / 1.9` 로 굽고 정수배로 늘린다. 안티에일리어싱도 끈다.
  화면만 각지고 초상만 매끈하면 그 매끈함이 오히려 더 튄다
- **색보정** — 셰이더와 같은 식(톤매핑 → 감마 → 채도 → 스플릿톤 → 대비 → 오더드 디더)을
  `eerie.gradePixels()` 로 JS 에서 한 번 더 쓴다. 비네트와 그레인만 뺐다 —
  30px 짜리 얼굴에 비네트를 걸면 그냥 어두워지기만 한다

**값은 표 하나(`eerie.PORTRAIT`)에서 같이 읽는다.** 식을 두 언어로 두 번 쓰는 건 어쩔 수 없지만
숫자를 두 군데 두면 다음에 만질 때 반드시 갈라진다.

초상만 대비를 화면보다 세게 준다(1.18 vs 1.14, lift 0.03 vs 0.05). 목록의 목적은
분위기가 아니라 **누가 누군지**이고, 그늘을 화면만큼 들어 올리면 얼굴이 전부 같은 톤이 된다.

손그림(`?cat=doodle`) 초상은 그림 파일 그대로라 손댈 자리가 없다 — CSS 필터 한 줄로 맞췄다.

기록증 카드 자체는 크림색 종이로 남겼다. 그건 게임 안의 **인쇄물**이고,
`이미지로 저장`·`복사` 로 밖으로 나가는 그림이라 화면 톤을 따라갈 물건이 아니다.

### 비용 — 아직 못 쟀다

구조상으로는 **더 쌀 가능성이 있다.** 무거운 장면은 417×236 에 그리고
전체 화면 한 장만 원래 해상도로 뽑기 때문이다(지금까지는 1500×900 × DPR 1.5 에 통째로 그렸다).
하루 종일 켜 두는 물건이라 이건 그냥 예쁨 문제가 아니다.

다만 **헤드리스(swiftshader)에서는 차이가 안 나온다** — 같은 조건으로 네 번 재서
파스텔 20.3·28.6 ms, eerie 22.2·26.7 ms 로 순서가 뒤집힌다. CPU 래스터라이저라
저해상도 이득과 풀스크린 채우기 손해가 뒤섞인다. **실측은 실제 GPU 에서 `2-power.html` 로.**

### 게임에 올렸다 (승격)

시안에서 기본값이 됐다. 승격하면서 시안 단계에서는 안 보이던 것들이 나왔다.

- **해상도 나누기를 화면 크기별로 갈랐다.** `PX = 3.4` 고정은 위젯 모드(380px)에서
  112px 짜리가 되어 고양이가 덩어리 세 개로 남았다. 지금은 `pxFor(w)` 로 2.0 / 2.6 / 3.4 —
  각진 정도는 "몇 배로 확대되는가" 가 아니라 "한 픽셀이 화면에서 몇 mm 인가" 로 읽히기 때문이다.
  (380×560 에서 내부 190×247. 읽힌다.)
- **모달·배치 모드·위젯 독이 전부 크림색으로 남아 있었다.** 시안은 사무실 화면만 봤고
  그것들은 "가끔 열리는 것" 이라 안 걸렸다. 특히 `.toast` 는 배경이 `var(--ink)` 였는데
  eerie 에서 `--ink` 가 밝아지면서 통째로 뒤집혔다 — **변수를 뒤집으면 변수를 쓰는 쪽도 뒤집힌다.**
- **후처리를 싱글턴에서 인스턴스로 갈랐다.** 프롤로그(`three/opening.js`)가 자기 렌더러를
  따로 갖기 때문이다. `createPass(renderer, scene, camera, opt)` 로 만들고,
  게임은 `install()`(안개 자동), 컷신은 `cutscenePass()`(안개·깜빡임 끔)를 쓴다.
- **프롤로그는 노출·비네트를 한 단계 눅였다** (exp .92 / vig .42 / sat .74).
  거긴 원래 비 오는 밤 골목이라 게임 값을 그대로 쓰면 회색 자갈밭이 된다.

되돌리는 자리: 설정(⚙️)의 [사무실 톤] · `?style=pastel` · `localStorage['copycat.style']='pastel'`.
확인한 경로는 기본 부팅 · 위젯 380px · 프롤로그 · 단일 파일 배포본(`file://`) · 파스텔 복귀 다섯이다.

## 7축 — 프롤로그 (`opening.js`) · 골목은 반대로 간다

사무실은 편안한 쪽으로 옮겼는데(6축) 프롤로그까지 같이 따뜻해지면
"사흘 동안 아무것도 못 먹었다" 가 안 된다. **같은 패스, 반대 값**으로 갈랐다.

| | 사무실(게임) | 골목(프롤로그) |
|---|---|---|
| 노출 `uExposure` | 0.80 | 1.06 |
| 채도 `uSat` | 0.82 | 0.54 |
| 비네트 `uVig` | 0.32 | 0.54 |
| 그늘 들어올리기 `uLift` | (.052,.046,.042) 따뜻 | (.018,.020,.034) 푸른기만 |
| 하이라이트 `uGain` | 따뜻 | 차갑게 |

질감(저해상도·오더드 디더·평면 셰이딩)은 같은 것을 쓴다. 그래서 두 장면이
"같은 게임의 두 시간대" 로 읽히고, 값만 갈려서 하나는 편안하고 하나는 우울하다.
후처리를 모듈 전역이 아니라 **인스턴스**로 만든 이유가 여기 있다 — 게임과 컷신은
렌더러가 서로 다르다(캔버스를 공유하지 않는다).

### 어두운 것과 우울한 것은 다르다

처음엔 팔레트를 통째로 내리고 전역광도 같이 내렸다. 결과는 우울한 골목이 아니라
**안 보이는 골목**이었다 — 오밀조밀하게 채워 넣은 것이 전부 검정에 묻혔다.

갈라 놓고 보니 규칙이 단순했다.

- **우울함은 색이 만든다** — 회청색에 **낡은 색**(녹 `0x5E4131`·때 `0x1B1F2B`·이끼 `0x333B2C`)을
  섞는다. 자판기 상품처럼 쨍한 색이 하나라도 남으면 그 장면만 안 우울하다
- **가독성은 빛이 만든다** — 배경을 내린 만큼 등불은 **올린다**(가로등 12 → 26).
  우울함은 "고른 어둠" 이 아니라 **빛 하나와 그 밖**이다
- 밤은 검정이 아니라 깊은 남색(`0x101426`)이다. 검정은 골목이 없어진 것이다

가로등 세기는 `step()` 이 매 프레임 다시 쓴다. 생성할 때 24 → 34 로 올려 놓고
화면이 그대로라 한참 헤맸다 — **매 프레임 덮어쓰는 값은 생성부에서 못 바꾼다.**

### 오밀조밀 — 벽이 절반이다

카메라가 고양이 눈높이(y 0.4~0.9)라 화면의 대부분이 벽이다. 바닥에 물건을 더 놓는 것보다
벽을 채우는 쪽이 눈에 훨씬 많이 들어온다.

- 창을 작고 촘촘하게 (1.5×2.1 간격 → 1.05×1.35). 켜진 것은 다섯에 하나
- 창 밑 **에어컨 실외기**, 벽을 타는 **배수관**과 브래킷, **계량기·배전함**
- **돌출 간판** 둘(하나만 켜짐), 낡은 포스터 조각 24장
- 오른쪽 벽에만 **비상계단** 3단 — 올려다보는 각도에서 하늘을 잘라 준다
- 골목을 가로지르는 **전선** 셋과 **빨랫줄**(천 조각 넷)
- 바닥: 맨홀·배수구 그레이트·상자 더미·맥주 크레이트·드럼통·파레트·쓰레기 봉투·버려진 우산
- 사무실 쪽도 같이: 안 푼 상자·접어 세운 의자·라디에이터·천장 배관·게시판·달력·시계·사다리·빗자루·바닥 얼룩

**난수는 씨앗을 고정했다.** `Math.random` 을 쓰면 다시 볼 때마다 창이 이사해서
"그날 밤 그 골목" 이 아니라 "비슷한 골목" 이 된다.

### 비용 — 물건을 늘렸으니 합친다

컷신에도 그대로 걸어서 정적인 것을 정점 색으로 구워 하나로 합쳤다.
합치면 안 되는 것은 `userData.dynamic` 으로 뺀다 — 발광(창·간판·자판기 유리·웅덩이),

## 아직 손으로 재야 하는 것

헤드리스로는 못 잰다. 여기가 진짜 갈림길이다.

### 1 — PiP (`1-pip.html`, 실제 브라우저에서)

`widget.js:139` 는 사본이 아니라 **원본 DOM 을 PiP 창으로 옮긴다.** DOM+CSS 면 그냥 살지만
WebGL 캔버스는 document 를 건너가면 컨텍스트를 잃을 수 있다.

```
① [PiP 열기]  → "이동 후 컨텍스트" 가 살아있음인가 LOST 인가
② 그 상태로 1초 프레임 수가 0 이 아닌가
③ 본 창을 최소화하고 [최근 2초 fps] 를 본다
④ 0 으로 떨어지면 [rAF 주인 바꾸기] 로 PiP 창에서 받아본다
```

③ 이 핵심이다. 도트 시절엔 CSS 애니메이션이 PiP 문서 쪽에서 돌아서 신경 쓸 일이 아니었는데,
WebGL 은 rAF 를 어느 window 에서 받느냐에 따라 본 창이 가려지는 순간 throttle 된다.
**하루 종일 켜 두는 게임에서 본 창은 거의 항상 가려져 있다.**

판정:
- 컨텍스트 유지 + rAF 를 PiP 창에서 받아 정상 → **3D 로 가도 된다**
- 컨텍스트 손실이지만 재생성이 200ms 안쪽 → 전환 때 한 번 깜빡인다. 참을 만하다
- 둘 다 안 되면 → 하이브리드(본 창 3D / 위젯 2D)거나, 3D 를 접는다

### 2 — 전력 (`2-power.html`, **충전기 뽑고**)

모드 하나당 최소 20분. `gl-always` ↔ `dom2d` 를 번갈아 재면 배경 소모가 상쇄된다.
`[CSV 내려받기]` 로 표본을 남긴다.

기준선은 지금의 copycat = `dom2d`. 보는 건 배수다.

- `gl-dirty`(변화 없을 때 안 그림) 가 `dom2d` 의 2배 이내 → 문제없다
- `gl-always` 가 5배 이상 → 위젯 모드는 무조건 `gl-10` / `gl-dirty` 로 강제해야 한다

`gl-dirty` 는 실제로 쓸 수 있는 모드다. 고양이 20마리가 늘 움직이는 것도 아니고,
자고 있거나 앉아 있으면 씬이 정지한다.
